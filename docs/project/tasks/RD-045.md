# RD-045: Native dialogs for GUI conflict and extension approval

Status: REVIEW
Priority: P1
Owner: agent
Reviewer: owner

## Goal

Show a native Wails dialog when ProxyBridge GUI conflicts with Apply, and once when the CLI asks for network-extension approval; remove the Dashboard Conflict banner.

## Context

Owner answers (2026-11-17): native dialogs only; scope A+C (GUI conflict + extension waiting for approval); approval dialog once per Apply while waiting, OK dismisses, do not auto-close after Allow; English copy structured for future i18n; remove Dashboard Conflict banner.

## Current behavior

Apply failures surface as Activity log lines and `operation.failed` snapshot refresh. Dashboard shows a Conflict banner that only mentions another CLI. Extension approval CLI lines are unclassified and silent to the user.

## Desired behavior

- GUI conflict → native Warning dialog (English, message IDs for i18n later)
- Extension approval line → native Info dialog once per Apply start; Apply keeps waiting
- Dashboard Conflict banner removed
- WaitConfirm conflict sets BridgeState `Conflict` (contract)

## Dependencies

None blocking. Owner product answers closed.

## Scope

- Classify `Extension: waiting for your approval...` as `extension_approval`
- Once-per-Start notify hook on ProxyBridge process
- Native `Dialog.Warning` / `Dialog.Info` with OK from composition root
- User-facing copy with stable message IDs (English until i18n)
- ProtectionService shows Warning on GUI conflict Apply failure
- Remove Dashboard `bridge === "Conflict"` banner
- Set `Conflict` when WaitConfirm fails with GUI/another CLI
- Update classifier contract note; STATUS / BACKLOG / HANDOFF

## Out of scope

- Another CLI dialog, extension timeout dialog, rejected-rules dialog
- Full i18n / locale packing
- React/Untitled modals
- Auto-dismiss when extension becomes active
- Killing foreign GUI/CLI
