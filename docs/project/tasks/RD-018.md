# RD-018: Logging foundation

Status: DONE
Priority: P0
Owner: agent
Reviewer: owner

## Goal

Wire structured `slog` logging to a rotating JSON file and stderr so every later adapter can leave an honest trail.

## Context

ADR-0008 and `docs/engineering/logging.md` define destinations, rotation, levels, and redaction. `main.go` still uses `log.Printf`.

## Current behavior

Ad-hoc `log.Printf` / `log.Fatal` only. No log file. No LevelVar. No redaction.

## Desired behavior

JSON log at `~/Library/Logs/route-deck/route-deck.log` (5 MiB, keep 3) plus text stderr via `slog.NewMultiHandler`. Shared `slog.LevelVar` (Info default). Redaction ReplaceAttr. Logger injected into Snapshotter/SnapshotService and `application.Options.Logger`. Stderr-only fallback if the log dir fails.

## Dependencies

- ADR-0008 Accepted
- `docs/engineering/logging.md` present

## Scope

- `internal/adapter/outbound/logfile` rotating writer + tests
- Logger assembly in `main.go`
- Replace `log.Printf`/`log.Fatal` in `main.go`
- Pass logger into existing services

## Out of scope

- Debug Settings toggle (RD-020/RD-030)
- Open logs folder UI (RD-030/RD-031)
- CLI line logging (RD-027)

## Acceptance criteria

- [x] `go test ./internal/adapter/outbound/logfile/...` PASS with rotation cases
- [x] `go test ./...` PASS

## Constraints

- MUST NOT add a custom Logger port
- MUST NOT add a third-party logging or rotation dependency
- MUST NOT log passwords, tokens, profile JSON, or Keychain data
- MUST NOT invent Wails APIs; verify `Options.Logger` under `vendor/`
