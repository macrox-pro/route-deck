# RD-044: Distinguish WARN and ERROR in RouteDeck logs

Status: REVIEW
Priority: P1
Owner: agent
Reviewer: owner

## Goal

Log operational failures as WARN and infrastructure failures as ERROR so Activity badges match severity.

## Context

Owner approved severity scale (2026-11-17). Activity shows `level` from JSON; almost all failures were logged with `slog.Info` plus `err`, so badges stayed INFO.

## Current behavior

`docs/engineering/logging.md` lists typed UI errors under Info. Call sites use `logger.Info("… failed", "err", err)`. Only Wails binding failures appear as ERROR.

## Desired behavior

| Level | When |
| --- | --- |
| INFO | Normal flow; every classified ProxyBridge CLI line (unchanged, ADR-0008) |
| WARN | Operational / expected: cancelled, desired profile not set, operation in progress, not installed, conflict, closed-port / probe and user-facing validation failures |
| ERROR | Unexpected infrastructure: Keychain, DB/settings/snapshot, apply/stop internal failure |

## Dependencies

None blocking. Owner severity decision closed.

## Scope

- Update `docs/engineering/logging.md` Level / What to log sections
- Retarget existing `Info(…"err"…)` / `* failed` call sites under `internal/`
- Add `service.ErrOperationInProgress` sentinel; use it for busy Apply/Stop
- Log WARN when Apply returns desired profile not set
- Apply/Stop failure logging: WARN for busy / not installed / conflict; ERROR otherwise
- Task index + STATUS + HANDOFF

## Out of scope

- Activity UI filters or ProxyBridge log tab
- Changing default LevelVar (stays Info; Debug toggle unchanged)
- Renaming slog attribute keys
- New ADR (policy lives in logging.md; ADR-0008 CLI-at-Info stays)

## Acceptance criteria

- [x] `logging.md` documents INFO / WARN / ERROR as above
