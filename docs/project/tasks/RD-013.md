# RD-013: Go code-quality gates for formatting and closed enums

Status: DONE
Priority: P0
Owner: agent
Reviewer: owner

## Goal

Make `golangci-lint run ./...` catch unformatted Go and non-exhaustive enum switches, fix the RD-008 parsers that slipped through, and write the rules down.

## Context

Owner review of `internal/domain` (2026-11-17) found code that passed the RD-008 lint gate but is not acceptable quality:

- `internal/domain/state.go` was not `gofmt`-formatted. `.golangci.yml` enables linters only, no formatters, so lint reported 0 issues.
- `ParseBridgeState`, `ParseProxyHealth`, `ParseProtectionState`, and `ParseProxyKind` convert the input twice (`switch T(s)` then `return T(s), nil`).
- Each closed list is written three times (constants, `case` list, test list). A new constant missing from the `case` list compiles, passes tests, and never parses. Nothing guards that.

Owner decision (2026-11-17, chat): fix all three, enforce them in lint, and record rules so agents do not write this again.

## Current behavior

- `golangci-lint run ./...` does not report formatting.
- No linter checks that a `switch` over an enum type lists every constant.
- Parsers repeat the conversion.
- `docs/engineering/golang.md` has no rule for formatting, repeated expressions, or closed enum switches.

## Desired behavior

- `.golangci.yml` enables the `gofmt` formatter and the `exhaustive` linter (default settings: `default` does not count as coverage).
- Each parser converts once into a local, switches on it, and returns it.
- `docs/engineering/golang.md`, `.cursor/rules/golang.mdc`, and `docs/operations/development.md` state the rules.

## Dependencies

- RD-008 DONE
- No blocking open ADR. ADR-0005 fixes the gate (`golangci-lint` + `.golangci.yml`), not the linter list

## Scope

- `internal/domain/state.go` — `gofmt` alignment (already applied); single conversion in three parsers
- `internal/domain/policy.go` — single conversion in `ParseProxyKind`
- `.golangci.yml` — add `exhaustive` to `linters.enable`; add `formatters.enable: [gofmt]` with the same `^build/` exclusion as linters
- `docs/engineering/golang.md` — MUST / MUST NOT rules and one Correct/Forbidden example for closed enum parsers
- `.cursor/rules/golang.mdc` — short form of the same rules
- `docs/operations/development.md` — note that lint covers formatting and enum exhaustiveness
- `docs/project/STATUS.md`, `docs/project/BACKLOG.md`, `docs/project/HANDOFF.md`
